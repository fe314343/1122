# TRT 藥劑配送 v2

本分支將客戶叫藥、管理員「收到」及庫存管理接到 Google 試算表。**需完成新版 Apps Script 部署與 config.js 設定後才合併到 main**；目前正式站仍使用 main 的舊程式。

## 包含的功能

- 弘大、永達、宏悅各自一個專屬連結，不需要輸入名稱；公司由後端驗證。
- 客戶用加減按鈕或數字輸入選藥，直接送出，沒有配送日期或訊息中心。
- 管理員看三家公司訂單；開啟清單後按「收到」，客戶看到狀態與處理時間。
- 下單不扣庫存；收到後整筆檢查庫存並預留；不足仍回覆收到，但不部分預留。
- 出貨只扣一次；取消解除預留；已出貨不可直接取消。
- 採購入庫、泡藥入庫及其他出庫，記錄原因與時間；手動出庫不能動用預留貨。
- 交易識別碼＋鎖定＋單列事件寫入，支援斷線後相同操作重送；不使用 no-cors 假成功。
- 可用庫存低於門檻顯示提醒：牛皮紙 ≤10 包、高分子 ≤1 包。MC2 不提醒。
- 舊的公司工作表保留，可由有權限的客戶讀取自己的舊紀錄；不重扣期初庫存。

## 通知現況（請勿當成已完成背景推播）

網站開啟且可見時，每 30 秒讀取一次最新訂單與狀態，發現更新會在網站顯示提示。
**目前沒有 Gmail、LINE、簡訊或網站關閉後的手機推播**，也不會假裝要求通知權限後就已接通推播。
要做到手機鎖定或關閉網站後跳通知，需要另行部署可控制網域、Service Worker 與 Web Push 後端，並逐一訂閱裝置；需實機驗證後才能交付給客戶。Apps Script HTML iframe 不是本版本的背景推播方案。

黑色活性碳兩週交期、FB 每次採購 50 包與自泡 24 桶/天僅顯示作業參數。歷史需求預測、實際泡藥排程、在途採購追蹤尚未實作，不會自動產生訂購日期。

## 檔案

- `index.html`：GitHub Pages 專屬連結入口；沒有公司/管理員切換。
- `config.js`：只放部署網址，**不可放任何憑證**。
- `apps-script/Code.gs`：後端及初始化。
- `apps-script/App.html`：Apps Script HTML Service 提供的實際操作頁，使用 `google.script.run` 取得可確認的結果，避開外部 fetch 的 CORS 問題。
- `apps-script/appsscript.json`：Asia/Taipei 時區及權限。
- `tests/`：可用 Node.js 內建測試執行，不需安裝套件。

## 初次部署（建議保留原專案作為回復途徑）

1. 備份目前試算表。建立**新的 Apps Script 專案**，避免直接覆蓋舊專案與仍在服務的舊部署。
2. 新專案的 `Code.gs` 貼上本分支 `apps-script/Code.gs`。建立 HTML 檔案，名稱 **App**，貼上 `App.html`。如要匯入資訊清單，可在專案設定開啟 appsscript.json 後貼入本分支對應檔案。
3. 在「專案設定 → 指令碼屬性」新增：
   - `SPREADSHEET_ID`：`16bkgufRUcJV4r7yhh5sNgv8s69F4dFmeOibuOC4zXzk`
   - `FRONTEND_URL`：你實際的 GitHub Pages 網址（包含正確路徑及結尾斜線）。
4. 在編輯器選取並執行 **`setupV2_`**，由擁有者完成 Google 授權。此函式只能在編輯器/試算表使用，不能被客戶透過 google.script.run 呼叫。
5. 確認試算表新增 `TRT_事件紀錄`、`TRT_專屬連結`。舊公司表不修改。期初庫存只建立一次：K1 86 桶、L1 43 桶、MC2 35 桶、S1 22 桶、牛皮紙 28 包、黑色 47 包、FB 40 包、高分子 8 包（2026-11-20 提供的快照）。不帶入展示版的假訂單/假預留。
6. 新增「網頁應用程式」部署：以擁有者身分執行；存取權允許預定的外部客戶進入。複製 **/exec** 網址，不用 /dev。
7. 將該網址填入本分支 `config.js` 的 `webAppUrl`。測試新部署時，可直接使用 `/exec?token=專屬憑證`；請勿把含憑證的網址貼進公開 issue、PR、程式碼或截圖。
8. 管理員及三家公司連結均從私人試算表的 `TRT_專屬連結` 取得。使用 `FRONTEND_URL#token=...` 入口會要求按一次進入，再轉到 Google 提供的實際操作頁。公司不能選擇或修改；不知道其他公司的憑證，就無法取得其資料。
9. 在三個獨立瀏覽器/無痕工作階段各測一家公司；使用管理員另開一個視窗。確認測試訂單、收到與出貨結果後，再合併本分支並讓 Pages 發佈。用正式庫存測試時，取消尚未出貨測試單；測試出貨請用有原因的反向入庫調整，勿刪事件。
10. 確認新入口可用後，再停用舊部署。**舊後端可能仍允許只用公司名稱讀取歷史紀錄，不能只更新新前端卻一直開著舊部署。** 專屬連結尚未送到客戶前，請規劃好切換時段。

未填部署網址時，新入口會顯示「尚未完成部署」，不會把請求送往舊後端，也不會顯示已成功下單。

## 日常使用

- 叫藥送出成功後才顯示新訂單；不確定是否成功時，用「重新整理」核對。
- 若送出期間網路斷線，保持同一頁重試相同操作，會沿用原交易編號。重新整理會失去尚未確認的交易編號，因此應先查訂單再決定是否重新下單。
- 管理員按收到只代表需求已讀，不代表一定有現貨；不足會顯示待補貨，入庫後按重新預留。
- 實際出貨從訂單按出貨，不要再做一次「其他出庫」。
- 事件紀錄是唯一帳本，勿手動刪改、排序單一欄或覆寫。現貨、預留、訂單都由同一帳本重算，避免多表寫一半。
- 若未來資料量大，需要事件快照/資料庫與分頁查詢；此版本每次操作讀取帳本，適用目前少量客戶的初期使用，尚未做大規模負載測試。

## 權限與連結遺失

試算表不要分享給客戶。`TRT_專屬連結` 有明文憑證，只有你與受信任的管理員可以查看；指令碼屬性只儲存憑證雜湊及身分。
專屬連結是持有即能使用的鑰匙。後端驗證每次讀取與異動，客戶無法以 companyName 參數冒用他家公司。管理員也是獨立憑證，不能傳給客戶。

若憑證外流：由擁有者在指令碼屬性刪除對應 `AUTH_<雜湊>`；刪除私人專屬連結表中對應的那一列；再執行 `setupV2_` 換發該身分的新連結（既有庫存不會重設）。切勿刪掉事件紀錄表。

## 驗證

```sh
node --test tests/*.test.cjs
```
